# marktplaats-scraper

Личный скрапер объявлений Marktplaats.nl для мониторинга цен на конкретные
модели ноутбуков (флиппинг). Не является публичным сервисом, не работает под
чужими аккаунтами, не обходит капчу автоматически.

## Как это устроено

Marktplaats — SPA на Next.js с server-side рендерингом. Есть два источника
структурированных данных со страницы поиска:

1. **Внутренний JSON API** `GET https://www.marktplaats.nl/lrp/api/search` —
   именно его дергает фронтенд. Недокументирован, может менять форму ответа
   и требовать антибот-заголовки без предупреждения.
2. **`__NEXT_DATA__`** — тот же JSON, что и (1), но embedded прямо в HTML
   страницы поиска (`<script id="__NEXT_DATA__">`), потому что это то, чем
   Next.js гидрирует страницу на клиенте. Не требует никаких скрытых
   заголовков/токенов — просто обычный HTML-запрос.

`scraper/fetch.py` сперва пробует (1), и если он не вернул объявлений —
откатывается на (2). `scraper/parse.py` умеет разбирать оба формата.

> Поля в JSON (например `priceInfo.priceCents`, `location.cityName`) — это
> добросовестная реконструкция по публично известной структуре Marktplaats.
> Точные названия полей могут отличаться на момент запуска. Прогоните
> `python main.py --query "laptop" --dump-raw raw.json` и сверьте реальный
> ответ, если что-то стабильно приходит пустым — код разбирает ответ
> defensively (несколько вариантов ключей + WARNING в лог, а не падение).

### robots.txt

`scraper/fetch.py` при старте скачивает и парсит `https://www.marktplaats.nl/robots.txt`
через `urllib.robotparser` и перед **каждым** запросом проверяет `can_fetch()`
для конкретного пути. Если robots.txt не удалось загрузить — скрипт **fail
closed**, то есть не делает вообще ни одного запроса, а не игнорирует правила.
Если сам robots.txt запрещает нужный путь — скрипт останавливается с логом
`robots.txt disallows ...` вместо того, чтобы его обойти.

## Структура проекта

```
marktplaats-scraper/
├── main.py            # CLI
├── filters.py          # фильтр по моделям + цене
├── storage.py           # SQLite, upsert по url
├── notify.py            # Telegram-алерт (заготовка)
├── config.yaml           # список моделей, цена, zipcode/radius, порог алерта
├── .env.example
├── requirements.txt
├── scraper/
│   ├── fetch.py    # HTTP-клиент: паузы, UA-ротация, backoff, бан-хендлинг
│   ├── parse.py    # JSON API + __NEXT_DATA__ HTML → Listing
│   ├── schema.py   # pydantic-модель Listing
│   └── enrich.py   # извлечение характеристик через Claude API
└── tests/
```

## Установка

```bash
cd marktplaats-scraper
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # заполнить реальными значениями
```

`.env`:

| Переменная | Обязательна | Назначение |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | нет | Алерт в Telegram при цене ниже порога |
| `TELEGRAM_CHAT_ID` | нет | Куда слать алерт |
| `ANTHROPIC_API_KEY` | нет (только для `--enrich`) | Извлечение CPU/RAM/SSD/дефектов через Claude |
| `PROXY_URL` | нет | `http://user:pass@host:port`, заготовка на случай проблем с IP |

Без Telegram/Anthropic переменных скрипт работает нормально — просто
пропускает алерты/enrichment и пишет об этом в лог, а не падает.

## Запуск

```bash
python main.py --query "thinkpad t480" --max-price 200 --zipcode 1011AB --radius 25
```

Полезные флаги:

- `--config config.yaml` — путь к конфигу со списком моделей/ценой/порогом алерта
- `--enrich` — прогнать Claude API по каждому объявлению, прошедшему фильтр (платно за вызов, поэтому включается явно)
- `--output results.json` — сохранить итоговый JSON
- `--dump-raw raw.json` — сохранить сырые (до фильтрации) объявления, полезно для отладки парсера
- `--max-requests N` — переопределить лимит запросов за прогон (по умолчанию 20)

Список моделей ноутбуков редактируется в `config.yaml` (`models:`). CLI
`--query` — это конкретный поисковый запрос к Marktplaats на этот прогон;
модели из конфига дополнительно используются как keyword-фильтр уже
полученных результатов.

## Расписание (cron)

Скрипт — одноразовый прогон, а не демон. Планируется через cron раз в 30-60
минут:

```cron
# каждые 45 минут
*/45 * * * * cd /path/to/marktplaats-scraper && .venv/bin/python main.py --query "thinkpad t480" --config config.yaml >> logs/cron.log 2>&1
```

Идемпотентность обеспечена `storage.py`: `url` — unique, повторный прогон
обновляет цену/last_seen у существующей записи, а не плодит дубликаты.

## Как не словить бан

- **Не увеличивай частоту запуска чаще, чем раз в 20-30 минут.** Каждый
  прогон и так делает несколько последовательных запросов с паузами — более
  частый cron просто складывает эти окна друг на друга.
- **Не запускай несколько инстансов параллельно** на разные модели
  одновременно. Объедини все интересующие модели в один `config.yaml`
  (`models:`) и делай один прогон с одним `--query` за раз — список моделей
  используется как фильтр уже полученной выдачи, а не как повод плодить
  параллельные сессии.
- Никакого многопоточного/параллельного скрапинга — `fetch.py` физически
  делает по одному запросу за раз, с случайной паузой `random.uniform(3, 7)`
  между ними (не фиксированной, чтобы паттерн не был регулярным).
- Жёсткий лимит **20 запросов за прогон** (`max_requests_per_run`) — при
  достижении скрипт останавливается сам, а не продолжает частить.
- При 403/429 или признаках капчи в ответе скрипт **не паникует и не
  ретраит агрессивно**: логирует `BAN_SIGNAL`, ждёт 15-30 минут (один раз) и
  повторяет запрос. Если и это не помогло — логирует `MANUAL_CHECK_NEEDED` и
  завершается с ненулевым кодом, ничего больше не пробуя. В этом случае
  **не запускай следующий cron-тик руками** — сначала зайди на сайт из
  обычного браузера и убедись, что тебя не блокируют.
- Мониторь здоровье скрапера через лог: `grep -E "BAN_SIGNAL|MANUAL_CHECK_NEEDED" logs/scraper.log`.
- `PROXY_URL` — заготовка на случай, если IP реально забанили; сама по себе
  не решает проблему частоты запросов, только смены адреса.
- Скрапер не обходит капчу автоматическими сервисами разгадывания и не
  работает под чужими аккаунтами — это осознанно не реализовано.

## Тесты

Сеть в CI/песочнице может быть недоступна (в частности — эта задача
собиралась в окружении, у которого сетевая политика блокирует исходящие
соединения к marktplaats.nl). Поэтому тесты работают на фикстурах —
реалистичном сэмпле JSON/`__NEXT_DATA__` HTML — и не ходят в сеть:

```bash
pytest
```

## Известные ограничения

- Точные названия полей в `/lrp/api/search` и структура `__NEXT_DATA__`
  собраны по публично известной информации о Marktplaats, а не сверены с
  живым ответом (см. раздел выше) — при первом реальном запуске сверь через
  `--dump-raw`.
- `--enrich` расходует Claude API кредиты за каждое объявление, прошедшее
  фильтр — включай осознанно.
- Официальный `api.marktplaats.nl` (partner API v1/v2) существует, но
  требует партнёрского доступа/апрува от Marktplaats — этот проект его не
  использует и ориентирован на публичный сайт для личного некоммерческого
  мониторинга.
