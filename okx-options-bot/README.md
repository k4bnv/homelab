# okx-options-bot

Каждые 15 минут анализирует BTC/ETH/SOL на OKX и торгует **OKX Event
Contracts** (`instType=EVENTS`, серии `{SYMBOL}-UPDOWN-15MIN`) на
**демо-счёте**: бинарные контракты "цена вырастет / упадёт за 15 минут",
те самые "События" из приложения OKX (Вверх/Вниз, окно вида
`11:30-11:45`). На каждый непустой сигнал реально размещает market-ордер
на покупку UP- или DOWN-контракта на `STAKE_USD`, контракт **сам
рассчитывается** по истечении 15-минутного окна (выплата 1 USDT за
выигравший контракт, 0 — за проигравший), P&L берётся из фактического
исполнения. Статистика (win rate, W/L, серии, просадка, equity-кривая,
таблица ставок) отдаётся веб-дашбордом.

Ордера **всегда** идут с заголовком `x-simulated-trading: 1`, который OKX
использует для маршрутизации в демо-движок — при включённом `OKX_DEMO=true`
(по умолчанию) реальных денег бот не трогает, торгует только демо-балансом
привязанного демо API-ключа. **Никогда не указывай сюда ключ от боевого
(live) аккаунта** — с ним `x-simulated-trading` не защитит от реальных
сделок. Bias-сигнал ("Bullish"/"Bearish"/"Neutral") — простая эвристика, не
финансовый совет.

## Как это работает

Раз в 15 минут (`POLL_INTERVAL_SECONDS`, по умолчанию 900с), для каждого
символа из `SYMBOLS`:

1. **Проверяет расчёт** открытой с прошлого цикла позиции (если есть) —
   смотрит `GET /api/v5/trade/fills` по её `instId`: если контракт уже
   рассчитан (запись с `subType` 414=выигрыш/415=проигрыш), фиксирует
   P&L (`fillPnl`) в БД. Если ещё не рассчитан (редко — окно уже должно
   было истечь к следующему циклу) — оставляет открытой и проверит снова
   через 15 минут.
2. **Технический анализ** базового актива — свечи `{SYMBOL}-USDT` бар 15m:
   RSI(14), MACD(12,26,9), EMA9/EMA21.
3. **Метрики опционного рынка** (вспомогательный сигнал, не торгуется
   напрямую) — сводка по `{SYMBOL}-USD` (`/api/v5/public/opt-summary`):
   ATM implied volatility, 25-delta skew, put/call open interest ratio.
4. Считает эвристический **bias** (Bullish/Bearish/Neutral) из технических
   и опционных сигналов.
5. Если |score| ≥ `BIAS_THRESHOLD` — находит текущее 15-минутное окно серии
   `{SYMBOL}-UPDOWN-15MIN` (`GET /api/v5/public/event-contract/markets`,
   `state=live`, окно с уже зафиксированным стартом и ближайшей
   экспирацией) и размещает market-ордер: `outcome=yes` (ставка на рост,
   Bullish) или `outcome=no` (ставка на падение, Bearish), `sz=STAKE_USD`
   (для market-ордеров на Event Contracts `sz` — это сразу сумма в USDT,
   без пересчёта в число контрактов), `tdMode=isolated`, `speedBump=1`
   (обязательные для этого типа контрактов параметры).

Если ордер отклонён биржей (`sCode != "0"`, например нехватка демо-баланса
или окно уже закрылось) или не исполнился за ~1.5с опроса — бот логирует
причину и пропускает цикл для этого символа, не ломая остальные.

Каждый цикл (по каждому символу) пишется в журнал (`activity_log` в БД):
время, bias и текст произошедшего ("opened ...", "settled ... pnl=...",
"neutral, no trade", причина пропуска и т.п.) — виден на дашборде в разделе
"Журнал циклов", не нужно смотреть `docker compose logs`.

## Настройка

```bash
cp .env.example .env
# ОБЯЗАТЕЛЬНО: OKX_API_KEY/SECRET/PASSPHRASE — создаются в OKX Demo Trading
# (переключатель Demo Trading в приложении/на сайте), права read+trade.
# Без ключей бот только читает публичные данные и ничего не торгует.
docker compose up -d --build
```

Дашборд: `http://<host>:8000` (порт настраивается через `HTTP_PORT`).
У интерфейса нет встроенной аутентификации — ограничивай доступ на уровне
сети/firewall/VPN, если разворачиваешь на публичном VPS.

Дашборд показывает баланс **только в USDT** с самого демо-счёта
(`GET /api/v5/account/balance?ccy=USDT`) — это настоящий источник правды
по деньгам, а не расчётная цифра бота.

## Переменные окружения

| Переменная | По умолчанию | Описание |
|---|---|---|
| `OKX_BASE_URL` | `https://www.okx.com` | REST endpoint OKX |
| `OKX_API_KEY` / `OKX_API_SECRET` / `OKX_API_PASSPHRASE` | пусто | нужны, чтобы бот реально торговал; без них — только чтение |
| `OKX_DEMO` | `true` | добавляет `x-simulated-trading: 1` ко всем запросам (демо-исполнение) |
| `SYMBOLS` | `BTC,ETH,SOL` | список активов через запятую — для каждого должна существовать серия `{SYMBOL}-UPDOWN-15MIN` |
| `CANDLE_BAR` | `15m` | таймфрейм свечей |
| `CANDLE_LIMIT` | `150` | сколько свечей запрашивать для индикаторов |
| `POLL_INTERVAL_SECONDS` | `900` | интервал цикла анализа/торговли (15 мин) |
| `BIAS_THRESHOLD` | `1` | порог \|score\| для входа в сделку, 1-4. Меньше = больше (слабее) сигналов, больше = меньше (сильнее) сигналов |
| `STAKE_USD` | `5.0` | размер ставки на сигнал, в USDT |
| `STAKE_USD_OVERRIDES` | пусто | per-symbol переопределение, напр. `BTC:10,ETH:5,SOL:2` |
| `STARTING_BANKROLL` | `1000.0` | стартовый баланс для расчётной статистики дашборда |
| `DB_PATH` | `./data/bets.db` | путь к SQLite с историей ставок |
| `HTTP_HOST` / `HTTP_PORT` | `0.0.0.0` / `8000` | адрес веб-дашборда |
| `LOG_LEVEL` | `INFO` | уровень логирования |

## Тесты

```bash
pip install -r requirements.txt
pytest
```

Тесты полностью офлайн: HTTP к OKX мокается через `respx`/фейковый клиент,
веб-API проверяется через `fastapi.testclient.TestClient`, реальные
сетевые вызовы (и тем более реальные ордера) не выполняются.

## Важно

Схема эндпоинтов Event Contracts (`/api/v5/public/event-contract/series`,
`/api/v5/public/event-contract/markets`, `/api/v5/trade/order` с
`outcome`/`speedBump`, `/api/v5/trade/fills`) восстановлена по исходникам
официального `okx/agent-trade-kit` и подтверждена живыми запросами к
демо-аккаунту (реальные `seriesId`: `BTC-UPDOWN-15MIN`, `ETH-UPDOWN-15MIN`,
`SOL-UPDOWN-15MIN`), а не по официальной документации напрямую (она была
недоступна из окружения разработки) — если OKX изменит формат ответов,
сверяйся с https://www.okx.com/docs-v5/en/ и/или
https://github.com/okx/agent-trade-kit.
