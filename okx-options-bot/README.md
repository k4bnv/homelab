# okx-options-bot

Каждые 15 минут анализирует BTC/ETH/SOL на OKX и отслеживает **OKX Event
Contracts** (`instType=EVENTS`, серии `{SYMBOL}-UPDOWN-15MIN`) — бинарные
контракты "цена вырастет / упадёт за 15 минут", те самые "События" из
приложения OKX (Вверх/Вниз, окно вида `11:30-11:45`).

**Реальных ордеров бот не размещает.** Стаканы по Event Contracts на
демо-счёте OKX не имеют ликвидности (подтверждено и через API, и вручную
в приложении — маркет- и лимит-ордера одинаково остаются неисполненными).
Вместо исполнения бот на каждый непустой сигнал просто фиксирует
предсказанное направление (UP/DOWN) в БД, а после экспирации окна
сверяет его с **реальным исходом того же контракта на бирже** (поле
`outcome`) — учёт по системе "на кону": угадал направление — `+ставка`,
не угадал — `-ставка`. Это честно измеряет качество самого сигнала
(угадывает ли он направление), не завися от того, есть ли сейчас
ликвидность для реального исполнения. Статистика (win rate, W/L, серии,
просадка, equity-кривая, таблица ставок) — на веб-дашборде.

Bias-сигнал ("Bullish"/"Bearish"/"Neutral") — простая эвристика, не
финансовый совет.

## Как это работает

Раз в 15 минут (`POLL_INTERVAL_SECONDS`, по умолчанию 900с), для каждого
символа из `SYMBOLS`:

1. **Проверяет расчёт** открытой с прошлого цикла "ставки" (если есть) —
   запрашивает тот же самый контракт (`GET /api/v5/public/event-contract/markets`
   по его `instId`) и смотрит поле `outcome`: `"0"` = ещё не рассчитан
   (оставляет открытой, проверит через 15 минут), `"1"` = реально победило
   UP, `"2"` = реально победило DOWN. Сравнивает с тем, что бот предсказал,
   и фиксирует WIN/LOSS + P&L (по чётным деньгам: `+STAKE_USD`/`-STAKE_USD`)
   в БД.
2. **Технический анализ** базового актива — свечи `{SYMBOL}-USDT` бар 15m:
   RSI(14), MACD(12,26,9), EMA9/EMA21.
3. **Метрики опционного рынка** (вспомогательный сигнал) — сводка по
   `{SYMBOL}-USD` (`/api/v5/public/opt-summary`): ATM implied volatility,
   25-delta skew, put/call open interest ratio.
4. Считает эвристический **bias** (Bullish/Bearish/Neutral) из технических
   и опционных сигналов.
5. Если |score| ≥ `BIAS_THRESHOLD` — находит текущее 15-минутное окно серии
   `{SYMBOL}-UPDOWN-15MIN` (`state=live`, окно с уже зафиксированным стартом
   и ближайшей экспирацией) и **записывает** предсказание: UP (Bullish) или
   DOWN (Bearish), без каких-либо ордеров.

Каждый цикл (по каждому символу) пишется в журнал (`activity_log` в БД):
время, bias и текст произошедшего ("opened (paper) ...", "settled ... pnl=...",
"neutral, no trade" и т.п.) — виден на дашборде в разделе "Журнал циклов",
не нужно смотреть `docker compose logs`.

## Настройка

```bash
cp .env.example .env
# ОБЯЗАТЕЛЬНО: OKX_API_KEY/SECRET/PASSPHRASE — даже "публичные" эндпоинты
# /api/v5/public/event-contract/* требуют подписанный запрос. Создаются в
# OKX Demo Trading, прав на торговлю не нужно (бот не размещает ордера) -
# read-only достаточно.
docker compose up -d --build
```

Дашборд: `http://<host>:8000` (порт настраивается через `HTTP_PORT`).
У интерфейса нет встроенной аутентификации — ограничивай доступ на уровне
сети/firewall/VPN, если разворачиваешь на публичном VPS.

Дашборд показывает баланс **только в USDT** с самого демо-счёта
(`GET /api/v5/account/balance?ccy=USDT`) — реальный демо-баланс, отдельно
от расчётной "бумажной" статистики бота.

## Переменные окружения

| Переменная | По умолчанию | Описание |
|---|---|---|
| `OKX_BASE_URL` | `https://www.okx.com` | REST endpoint OKX |
| `OKX_API_KEY` / `OKX_API_SECRET` / `OKX_API_PASSPHRASE` | пусто | нужны для чтения данных Event Contracts; без них бот вообще не работает |
| `OKX_DEMO` | `true` | добавляет `x-simulated-trading: 1` ко всем запросам |
| `SYMBOLS` | `BTC,ETH,SOL` | список активов через запятую — для каждого должна существовать серия `{SYMBOL}-UPDOWN-15MIN` |
| `CANDLE_BAR` | `15m` | таймфрейм свечей |
| `CANDLE_LIMIT` | `150` | сколько свечей запрашивать для индикаторов |
| `POLL_INTERVAL_SECONDS` | `900` | интервал цикла анализа (15 мин) |
| `BIAS_THRESHOLD` | `2` | порог \|score\| для фиксации сигнала, 1-4. Меньше = больше (слабее) сигналов, больше = меньше (сильнее) сигналов |
| `STAKE_USD` | `5.0` | размер виртуальной ставки на сигнал, в USDT (учёт по чётным деньгам) |
| `STAKE_USD_OVERRIDES` | пусто | per-symbol переопределение, напр. `BTC:10,ETH:5,SOL:2` |
| `STARTING_BANKROLL` | `1000.0` | стартовый баланс для расчётной статистики дашборда |
| `DB_PATH` | `./data/bets.db` | путь к SQLite с историей ставок |
| `HTTP_HOST` / `HTTP_PORT` | `0.0.0.0` / `8000` | адрес веб-дашборда |
| `LOG_LEVEL` | `INFO` | уровень логирования |


## Важно

Схема эндпоинтов Event Contracts (`/api/v5/public/event-contract/series`,
`/api/v5/public/event-contract/markets`) восстановлена по исходникам
официального `okx/agent-trade-kit` и подтверждена живыми запросами к
демо-аккаунту (реальные `seriesId`: `BTC-UPDOWN-15MIN`, `ETH-UPDOWN-15MIN`,
`SOL-UPDOWN-15MIN`), а не по официальной документации напрямую (она была
недоступна из окружения разработки) — если OKX изменит формат ответов,
сверяйся с https://www.okx.com/docs-v5/en/ и/или
https://github.com/okx/agent-trade-kit.

Клиент (`app/okx_client.py`) всё ещё умеет размещать/отменять реальные
ордера (`place_order`, `cancel_order`, `get_fills`) — эти методы просто не
вызываются торговым циклом сейчас, раз ликвидности для исполнения нет. Если
OKX добавит ликвидность на демо-счёт для Event Contracts, вернуть реальное
исполнение — вопрос переиспользования уже готовых методов в `bet_engine.py`.
