# okx-options-bot

Каждые 15 минут анализирует опционы BTC/ETH на OKX и торгует ими на
**демо-счёте OKX**: на каждый непустой сигнал реально размещает market-ордер
на покупку ATM-опциона на ≈$5 виртуального демо-баланса, закрывает позицию
офсетным ордером на следующем цикле (~15 мин) и считает P&L по фактическим
ценам исполнения. Статистика (win rate, W/L, серии, просадка, equity-кривая,
таблица ставок) отдаётся веб-дашбордом.

Ордера **всегда** идут с заголовком `x-simulated-trading: 1`, который OKX
использует для маршрутизации в демо-движок — при включённом `OKX_DEMO=true`
(по умолчанию) реальных денег бот не трогает, торгует только демо-балансом
привязанного демо API-ключа. **Никогда не указывай сюда ключ от боевого
(live) аккаунта** — с ним `x-simulated-trading` не защитит от реальных
сделок. Bias-сигнал ("Bullish"/"Bearish"/"Neutral") — простая эвристика, не
финансовый совет.

## Как это работает

Раз в 15 минут (`POLL_INTERVAL_SECONDS`, по умолчанию 900с), для каждого
символа из `SYMBOLS`:

1. **Закрывает** открытую с прошлого цикла позицию (если есть) — отправляет
   market sell на весь объём контрактов, ждёт исполнения
   (`GET /api/v5/trade/order`) и считает P&L по фактической цене выхода.
2. **Технический анализ** базового актива — свечи `{SYMBOL}-USDT` бар 15m:
   RSI(14), MACD(12,26,9), EMA9/EMA21.
3. **Метрики опционного рынка** — сводка по `{SYMBOL}-USD`
   (`/api/v5/public/opt-summary`) для ближайшей экспирации: ATM implied
   volatility, 25-delta skew, put/call open interest ratio, OI-взвешенные
   греки.
4. Считает эвристический **bias** (Bullish/Bearish/Neutral) из технических
   и опционных сигналов.
5. Если |score| ≥ `BIAS_THRESHOLD` — **открывает** новую позицию: размещает
   market buy на ATM call (Bullish, score ≥ порога) или ATM put (Bearish,
   score ≤ -порога) ближайшей экспирации. Размер ордера подбирается под
   `STAKE_USD` (или его per-symbol override) по текущей `askPx`, затем
   округляется вниз до `lotSz` инструмента (не ниже `minSz`) — фактическая
   стоимость входа может отличаться от `STAKE_USD` и записывается в БД как
   есть.

Контракты OKX могут быть маржированы в USD/USDT/USDC (премия уже в
долларах) или в монете базового актива (премия в BTC/ETH) — конвертация в
USD учитывает `ctVal`/`ctValCcy` инструмента и текущий спот.

Если ордер отклонён биржей (`sCode != "0"`, например нехватка демо-баланса)
или не исполнился за ~1.5с опроса — бот логирует причину и пропускает цикл
для этого символа, не ломая остальные. Стакан по опциону иногда пуст (нет
`askPx`/`bidPx`) — тогда для оценки размера позиции используется `markPx`
(модельная цена OKX), сам ордер остаётся market-ордером.

Каждый цикл (по каждому символу) пишется в журнал (`activity_log` в БД):
время, bias и текст произошедшего ("opened ...", "closed ... pnl=...",
"neutral, no trade", причина пропуска и т.п.) — виден на дашборде в разделе
"Журнал циклов", не нужно смотреть `docker compose logs`.

## Настройка

```bash
cp .env.example .env
# ОБЯЗАТЕЛЬНО: OKX_API_KEY/SECRET/PASSPHRASE — создаются в OKX Demo Trading
# (переключатель Demo Trading в приложении/на сайте), права read+trade.
# Без ключей бот только читает публичные данные и ничего не торгует.
docker compose up -d --build
```

Дашборд: `http://<host>:8000` (порт настраивается через `HTTP_PORT`).
У интерфейса нет встроенной аутентификации — ограничивай доступ на уровне
сети/firewall/VPN, если разворачиваешь на публичном VPS.

Дашборд показывает два разных "баланса": **Balance** — расчётный от
`STARTING_BANKROLL` + сумма P&L закрытых ставок бота (для статистики
win/loss), и отдельная панель **"Баланс OKX (демо-счёт)"** — живой
`totalEq` с самого аккаунта (`GET /api/v5/account/balance`), это настоящий
источник правды по деньгам на демо-счёте (учитывает комиссии, чужие
сделки на этом же аккаунте и т.п., если они есть).

## Переменные окружения

| Переменная | По умолчанию | Описание |
|---|---|---|
| `OKX_BASE_URL` | `https://www.okx.com` | REST endpoint OKX |
| `OKX_API_KEY` / `OKX_API_SECRET` / `OKX_API_PASSPHRASE` | пусто | нужны, чтобы бот реально торговал; без них — только чтение |
| `OKX_DEMO` | `true` | добавляет `x-simulated-trading: 1` ко всем запросам (демо-исполнение) |
| `OKX_TD_MODE` | `cash` | trade mode для ордеров на покупку/продажу опциона |
| `SYMBOLS` | `BTC,ETH` | список базовых активов через запятую |
| `CANDLE_BAR` | `15m` | таймфрейм свечей |
| `CANDLE_LIMIT` | `150` | сколько свечей запрашивать для индикаторов |
| `POLL_INTERVAL_SECONDS` | `900` | интервал цикла анализа/торговли (15 мин) |
| `BIAS_THRESHOLD` | `1` | порог \|score\| для входа в сделку, 1-4. Меньше = больше (слабее) сигналов, больше = меньше (сильнее) сигналов |
| `STAKE_USD` | `5.0` | целевой размер позиции на сигнал (факт может отличаться из-за lot size) |
| `STAKE_USD_OVERRIDES` | пусто | per-symbol переопределение, напр. `BTC:10,ETH:5,SOL:2` |
| `STARTING_BANKROLL` | `1000.0` | стартовый баланс для дашборда (для отображения, не привязан к реальному демо-балансу OKX) |
| `DB_PATH` | `./data/bets.db` | путь к SQLite с историей ставок |
| `HTTP_HOST` / `HTTP_PORT` | `0.0.0.0` / `8000` | адрес веб-дашборда |
| `LOG_LEVEL` | `INFO` | уровень логирования |

## Тесты

```bash
pip install -r requirements.txt
pytest
```

Тесты полностью офлайн: HTTP к OKX мокается через `respx`/фейковый клиент,
веб-API проверяется через `fastapi.testclient.TestClient`, реальные
сетевые вызовы (и тем более реальные ордера) не выполняются.

## Важно

Схема эндпоинтов OKX v5 (`/api/v5/market/candles`, `/api/v5/market/ticker`,
`/api/v5/public/mark-price`, `/api/v5/public/instruments`,
`/api/v5/public/opt-summary`, `/api/v5/public/open-interest`,
`/api/v5/trade/order`, `/api/v5/account/balance`) реализована по
официальной документации OKX и может со временем меняться на их стороне —
перед тем как доверять цифрам P&L, стоит сверить актуальные поля ответа
(особенно `ctVal`/`ctValCcy` для расчёта стоимости контракта в USD и
`tdMode`-требования для опционов) с https://www.okx.com/docs-v5/en/.
